# 数值平衡表 v1（Q3 交付 · Qoder）

> 依据：`docs/qoder/sim.mjs` 对 2000 seeds 的实测（bot = 贪心吃砖模拟器，`botRun`，横移极限 9m/s）。
> 原则：**bot 通关率是上限不是预期**——真人会漏砖、走线差，一般取 真人 ≈ bot × 0.6~0.8。
> 所以关卡设计目标带：L1 bot≥98%，L5 bot≥90%，L10 bot≥75%；单局时长 20→45s 递增。

## 手感参数（不随关卡变，全局常量）

| 字段 | 值 | 依据 |
|---|---|---|
| steerSpeed | 10 | 横移插值，>12 发飘 <8 迟钝（行业惯例 8~15 取中） |
| steerPerPixel | 0.022 | 一屏宽≈720px→全宽 15.8m，够 2 个身位/屏 |
| keySteerSpeed | 4 | 仅调试用 |
| trackHalfWidth | 2.6 | 5.2m 道宽 ≈ 3 个角色身位，够躲不吃错砖 |

## 验收断言（进 sim.mjs 回归）

1. 每关 60 seeds：L1-L3 bot 通关率 ≥95%，L4-L7 ≥90%，L8-L10 ≥80%（v2 生成器下）。
2. 单局 bot 时长：L1 ∈ [15, 25]s，L10 ∈ [30, 50]s。
3. 难度单调：平均断崖数随 level 不减，L10/L1 ≥ 2.0。
4. 前缀可行率 = 100%（D2 修复不许回归）、全局缺砖率 = 0（D1 修复不许回归）。

## 已知风险 / 待定

- bot 不会"贪心失败"（贴边砖漏吃），真人漏砖率未知 → G1 试玩后按数据回调 gateCost。
- L1 winRate 实测 59/60 的失败 seed 是双砖同 z 反向布局 → 若 G1 后仍要更平滑，给 genLevelV2 加"同区间两拾取 z 间距 ≥4m"约束（一行改动，先不做，避免过度设计）。
