# K2 · 包体预算与瘦身方案

> 归属：K2 · 依据：`docs/wechat-build.md`（≤4MB）、当前工程"纯代码无资源"实况
> 消费方：step-5 在构建配置执行

## 1. 红线

| 项 | 值 | 来源 |
|---|---|---|
| 微信小游戏主包上限 | **4 MB** | 微信官方 |
| 主包建议留白 | ≤3.6 MB（留 10% 余量） | 防审核期增量 |
| 分包单包上限 | 4 MB | 官方 |
| 总包上限（主+分） | 20 MB | 官方 |

## 2. 当前体积账（估算，待 build 产物实测校准）

| 内容 | 预估 | 压缩后 | 说明 |
|---|---|---|---|
| Cocos 3D 引擎（裁剪后） | — | ~2.5-3.5 MB | 基线大头，**唯一可动的大头** |
| 我们的代码/场景 | <50 KB | <50 KB | 纯 TS，无 prefab 资源 |
| 音效 4 件套 | ~300 KB | ~300 KB | 可降为 **0**（WebAudio 合成已双端验证） |
| 主题/皮肤/额外关卡 | 0 | 0 | 走 CDN 或代码生成 |
| **合计** | | **≈2.9-3.9 MB** | 贴红线，余量小 |

**结论**：本项目体积几乎全在引擎。**不用担心美术资产（本来就没有）**，要担心的是引擎裁剪未开。

## 3. 超限处置阶梯（按性价比排序，逐级执行）

| 级 | 手段 | 收益 | 代价 | 触发条件 |
|---|---|---|---|---|
| **L0** | 引擎模块裁剪：构建面板关闭未用模块（物理/粒子/骨骼动画 Spine/视频/TiledMap/2D 物理） | **省 0.5-1.5 MB** | 需验证功能不回退 | 首选，必做 |
| **L1** | 音效改 WebAudio 合成（浏览器版已验证路线） | 省 ~300 KB | 微信端兼容性需真机验 | 超 3.8MB |
| **L2** | 开启构建压缩（微信小游戏自带 gzip/brotli）+ 移除 sourceMap | 省 20-40% | 无 | 必做 |
| **L3** | 资源分包（`bundle` 配置远程/CDN 加载） | 主包只留核心 | 需域名白名单 + 首次加载等待 | 超 4MB |
| **L4** | 引擎定制裁剪（`cocos-engine` 源码级剔除） | 大头，可到 1.5MB 级 | 工程复杂度上升很多 | 前四级仍超 |
| **L5** | 换轻量引擎（Three.js 版已有 `web-preview` 基线） | 主包可 <1MB | 重写工程，不推荐 | 极端兜底 |

**执行顺序：L0 + L2 先做（几乎零成本），不够再上 L1，仍不够才 L3。**

## 4. 构建配置清单（step-5 勾选）

- [ ] 平台：微信小游戏，发布路径 `build/wechatgame`
- [ ] **MD5 Cache 关闭**（会膨胀）
- [ ] **Source Maps 关闭**
- [ ] **引擎模块裁剪**（见 L0 模块表）
- [ ] 屏幕方向：竖屏；设计分辨率 720×1280
- [ ] 构建后跑 `node docs/k2/check-bundle.mjs build/wechatgame` 体检

## 5. 机验口径

```bash
node docs/k2/check-bundle.mjs build/wechatgame
```
脚本输出：主包总字节 / 各子目录占比 / Top10 大文件 / 是否越线 / 越线时的下一级建议。退出码 0=通过，1=越线。

**通过标准**：主包 ≤3.6MB（留白），且不存在单文件 >1MB 的非引擎资源。
